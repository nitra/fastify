# Відмова сервісу показується в браузері як «Failed to fetch» - план імплементації

Бізнес-план: docs/business-plan/cors-on-request/business-plan.md

## Зміни в бібліотеці

1. Перенести додавання дозволу для браузера з пізнього етапу обробки запиту на найперший — до будь-яких перевірок, які можуть додати сервіси. Значення дозволу й правило, звідки береться дозволений сайт, лишаються як є. Прив'язка логів до запиту лишається на тому ж етапі, що й зараз.
2. Обробник preflight-запитів не змінюється: він і далі віддає лише час кешування, а сам дозвіл тепер ставиться на першому етапі.
3. Підняти патч-версію пакета до 2.5.10 — публікація відбувається лише за зміни версії.

## Доставка

1. Злиття в основну гілку бібліотеки — CI публікує патч-версію 2.5.10. Діапазон версій у сервісах її приймає, тож змінювати залежності не потрібно.
2. smart2, EDI: оновити бібліотеку до 2.5.10 і прибрати тимчасову латку разом із її коментарем, перевірити за критеріями прийомки.
3. Решта сервісів отримує виправлення під час звичайного оновлення залежностей; окремих дій не потрібно.
